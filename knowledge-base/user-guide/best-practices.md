# 最佳实践指南

## 1. 需求编写最佳实践

### 1.1 Bug 需求

**好的 Bug 描述：**

```markdown
## Bug 标题
用户登录时随机出现 500 错误

## 环境
- 版本：v2.1.0
- 浏览器：Chrome 120
- 操作系统：Windows 11

## 复现步骤
1. 打开登录页面
2. 输入有效的用户名和密码
3. 点击登录按钮
4. 约 5% 的情况会出现 500 错误

## 预期结果
登录成功，跳转到首页

## 实际结果
显示 500 Internal Server Error

## 错误日志
```
ConnectionPoolError: Connection pool exhausted
  at DatabasePool.acquire (db/pool.js:45)
```

## 影响范围
影响约 5% 的用户登录
```

**避免的描述方式：**
- ❌ "登录有问题"
- ❌ "系统报错了"
- ❌ "不能用了"

### 1.2 Feature 需求

**好的 Feature 描述：**

```markdown
## 功能标题
批量用户导出功能

## 背景
管理员需要定期导出用户数据进行分析

## 需求描述
1. 支持导出 CSV 和 Excel 格式
2. 可选择导出字段（姓名、邮箱、注册时间等）
3. 支持按时间范围筛选
4. 大数据量时支持异步下载

## 验收标准
- [ ] 导出 10000 条数据耗时 < 30 秒
- [ ] 导出文件格式正确
- [ ] 敏感字段支持脱敏

## 相关文档
- [数据安全规范](link)
- [UI 原型](link)
```

### 1.3 通用建议

| 要素 | 建议 |
|------|------|
| **标题** | 简洁明确，包含关键信息 |
| **描述** | 提供足够的上下文 |
| **步骤** | 清晰的复现或操作步骤 |
| **预期** | 明确的验收标准 |
| **附件** | 必要的截图和日志 |

## 2. AI 交互最佳实践

### 2.1 高效提问

**结构化提问：**

```
我需要了解 [具体问题]

背景：[相关上下文]

具体问题：
1. [问题1]
2. [问题2]

期望获得：[期望的答案形式]
```

**示例：**

```
我需要了解这个 500 错误的根本原因

背景：
- 错误发生在用户登录时
- 约 5% 的请求会出错
- 高峰期更容易复现

具体问题：
1. 可能的根本原因是什么？
2. 如何验证这个原因？
3. 推荐的修复方案是什么？

期望获得：详细的分析和修复建议
```

### 2.2 迭代对话

**第一轮**：提出问题
```
分析这个 Bug 的原因
```

**第二轮**：深入追问
```
你提到可能是数据库连接问题，能详细解释一下吗？
```

**第三轮**：确认方案
```
如果用 connection pool 的方式修复，需要修改哪些代码？
```

### 2.3 提供上下文

**有效上下文：**
- 相关的错误日志
- 系统配置信息
- 代码片段
- 业务背景

**示例：**
```
这是相关的错误日志：
[粘贴日志]

这是当前的数据库配置：
[粘贴配置]

请基于这些信息分析问题
```

## 3. 审核最佳实践

### 3.1 审核原则

| 原则 | 说明 |
|------|------|
| **及时性** | 收到审核请求后尽快处理 |
| **完整性** | 审查方案的所有方面 |
| **建设性** | 提供有帮助的反馈 |
| **客观性** | 基于事实判断 |

### 3.2 审核要点

**Bug 修复方案：**
- [ ] 根因分析是否准确
- [ ] 修复方案是否彻底
- [ ] 是否有副作用
- [ ] 测试覆盖是否充分
- [ ] 回滚方案是否可行

**Feature 设计方案：**
- [ ] 是否满足需求
- [ ] 架构设计是否合理
- [ ] API 设计是否规范
- [ ] 是否考虑边界情况
- [ ] 性能是否可接受

### 3.3 审核反馈

**好的反馈：**
```
修复方案整体合理，但有以下建议：

1. 第 45 行的异常处理可以更细化，建议区分不同类型的错误
2. 建议增加连接池监控指标，便于后续排查
3. 测试用例建议增加并发场景的测试

修改后可以通过。
```

**避免的反馈：**
- ❌ "不行"
- ❌ "重做"
- ❌ "看起来有问题"（没有具体说明）

## 4. 代码生成最佳实践

### 4.1 方案描述

方案越详细，生成的代码质量越高：

**好的方案描述：**
```
## 实现方案

### 数据层
- 使用 PostgreSQL 存储导出任务
- 表结构：id, status, format, filters, file_url, created_at

### 服务层
- ExportService 负责导出逻辑
- 使用 streaming 方式处理大数据
- 支持 CSV 和 Excel 格式

### API 层
- POST /exports - 创建导出任务
- GET /exports/{id} - 获取任务状态
- GET /exports/{id}/download - 下载文件

### 异步处理
- 使用 Celery 处理导出任务
- 超过 1000 条数据采用异步
```

### 4.2 代码审查

生成代码后必须审查：

**审查清单：**
- [ ] 逻辑正确性
- [ ] 边界情况处理
- [ ] 异常处理
- [ ] 安全性
- [ ] 性能
- [ ] 代码风格

### 4.3 迭代优化

如果生成的代码不满意：
1. 指出具体问题
2. 提供修改建议
3. 要求重新生成

## 5. 测试最佳实践

### 5.1 测试覆盖

| 场景 | 覆盖率目标 |
|------|------------|
| 核心逻辑 | >90% |
| 边界情况 | >80% |
| 异常处理 | >70% |

### 5.2 测试类型

- **单元测试**：测试单个函数
- **集成测试**：测试组件协作
- **E2E 测试**：测试完整流程

### 5.3 失败处理

测试失败时：
1. 查看错误信息
2. 分析失败原因
3. 修复代码或测试
4. 重新运行
