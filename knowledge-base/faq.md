# 常见问题解答 (FAQ)

## 一、基础问题

### Q1: OpsPilot 是什么？

OpsPilot 是一个智能研发流程自动化平台，利用 AI 技术自动化处理需求分析、Bug 修复、功能设计、代码生成等研发任务。它基于 DeerFlow 2.0 框架构建，采用 Lead Agent + Sub-Agents 架构。

### Q2: OpsPilot 支持哪些编程语言？

目前主要支持：
- **Python** - 完整支持
- **TypeScript/JavaScript** - 完整支持
- **Java** - 支持
- **Go** - 支持

后续会继续扩展语言支持。

### Q3: OpsPilot 需要什么 AI API？

支持多种 AI 服务提供商：
- **OpenAI** - GPT-4o, GPT-4-turbo
- **DeepSeek** - DeepSeek-Chat, DeepSeek-Coder
- **Anthropic** - Claude 3.5 Sonnet

至少需要配置一个 AI API Key。

### Q4: OpsPilot 如何保证数据安全？

- 数据存储在您自己的服务器
- 支持本地部署
- AI API 通信加密
- 不存储敏感代码到第三方

## 二、部署问题

### Q5: 最低硬件配置是什么？

| 组件 | 最低要求 |
|------|----------|
| CPU | 2 核 |
| 内存 | 4GB |
| 磁盘 | 20GB |

推荐配置为 4 核 CPU、8GB 内存、50GB 磁盘。

### Q6: 支持 Windows 部署吗？

是的，支持两种方式：
1. **Docker Desktop** - 推荐，配置简单
2. **本地开发环境** - 需要手动安装依赖

详见 [Windows 部署指南](../docs/windows-deployment-guide.md)。

### Q7: 如何升级版本？

Docker 部署：
```bash
git pull origin main
docker-compose build
docker-compose up -d
docker-compose exec backend alembic upgrade head
```

### Q8: 如何备份数据？

```bash
# 备份数据库
docker-compose exec db pg_dump -U opspilot opspilot > backup.sql

# 备份上传文件
tar -czf uploads.tar.gz uploads/
```

## 三、使用问题

### Q9: AI 分析需要多长时间？

| 任务类型 | 预计时间 |
|----------|----------|
| 简单需求分析 | 10-20 秒 |
| 复杂需求分析 | 30-60 秒 |
| 方案生成 | 30-90 秒 |
| 代码生成 | 30-120 秒 |

时间取决于需求复杂度和 AI 服务响应速度。

### Q10: 为什么 AI 分析结果不准确？

可能的原因：
1. **需求描述不够详细** - 提供更多上下文
2. **缺少相关知识** - 上传相关文档到知识库
3. **问题本身复杂** - 分步骤逐步分析

建议：
- 提供更详细的需求描述
- 补充错误日志和代码片段
- 与 AI 进行多轮对话深入分析

### Q11: 生成的代码能直接使用吗？

AI 生成的代码需要人工审查：
- 检查业务逻辑正确性
- 验证边界情况处理
- 确认代码风格符合规范
- 运行测试验证

建议将生成的代码作为起点，根据实际情况调整。

### Q12: 如何提高代码生成质量？

1. **详细的方案描述** - 越详细越好
2. **提供代码示例** - 参考现有代码风格
3. **上传项目文档** - 让 AI 了解项目背景
4. **迭代优化** - 反馈问题让 AI 改进

## 四、审核问题

### Q13: 为什么需要人工审核？

HITL（Human-in-the-Loop）机制确保：
- AI 方案的准确性
- 风险可控
- 符合业务需求
- 责任明确

### Q14: 审核超时怎么办？

超时后系统会：
1. 发送提醒通知
2. 自动转给备选审核人
3. 升级给管理员

### Q15: 可以跳过审核吗？

可以在项目设置中配置 `require_review: false`，但不推荐在生产环境使用。

## 五、集成问题

### Q16: 如何与 Jira 集成？

1. 进入 **设置 > 集成 > Jira**
2. 填写 Jira 配置：
   - Jira URL
   - 用户名
   - API Token
3. 配置同步选项
4. 测试连接

### Q17: 支持哪些代码仓库？

- **GitHub** - 完整支持
- **GitLab** - 完整支持
- **Bitbucket** - 基础支持

### Q18: 如何接收通知？

支持的通知渠道：
- **系统内通知** - 默认开启
- **邮件通知** - 需要配置 SMTP
- **Webhook** - 自定义 Webhook 地址

## 六、故障排除

### Q19: 系统无法访问？

检查步骤：
1. 确认服务是否运行：`docker-compose ps`
2. 检查端口是否被占用：`lsof -i :3000`
3. 查看日志：`docker-compose logs`

### Q20: AI 服务连接失败？

检查步骤：
1. 确认 API Key 正确
2. 检查网络连接
3. 验证 API 配额
4. 尝试使用备用模型

### Q21: 数据库连接错误？

检查步骤：
1. 确认数据库服务运行
2. 检查连接字符串
3. 验证用户名密码
4. 检查网络和防火墙

### Q22: 前端页面空白？

可能原因：
- API URL 配置错误
- 后端服务未启动
- 浏览器缓存问题

解决方法：
```bash
# 检查后端
curl http://localhost:8000/api/v1/health

# 清理前端缓存
npm run build
```

## 七、性能问题

### Q23: 系统响应很慢？

优化建议：
1. 增加服务器资源
2. 配置 Redis 缓存
3. 优化数据库索引
4. 使用 CDN 加速静态资源

### Q24: 大数据量处理慢？

建议：
1. 分批处理数据
2. 使用异步任务
3. 增加数据库连接池
