# M2 - 项目信息与知识库前置维护 · 页面原型说明

本文档描述 M2 模块各页面的**原型结构、布局、组件与交互**，遵循 [页面原型风格规范.md](页面原型风格规范.md)。可配合 `docs/prototypes/m2/` 下的 HTML 静态原型查看效果。

---

## 1. 页面清单与路由

| 序号 | 页面名称 | 路由（示例） | 说明 |
|------|----------|--------------|------|
| P1 | 项目信息概览 | `/projects/:id/knowledge` | 当前项目信息摘要、就绪状态、编辑入口 |
| P2 | 编辑项目信息 | `/projects/:id/knowledge/edit` | 项目概述、架构、目录、配置、Runbook 等表单 |

**入口**：从 M1 项目详情页「知识库」卡片点击「去维护」进入 P1；从 P1 点击「编辑」进入 P2。

---

## 2. 全局布局（所有页面共用）

- **顶栏**：高度 56px，背景 #FFFFFF，下边框 1px #E5E7EB；左侧 Logo +「运维 Agent 工作台」；右侧「项目管理」「工作台」导航 + 用户头像下拉。
- **侧栏**：宽度 220px，背景 #FFFFFF，右边框 1px #E5E7EB；当前项目下展示「概览」「需求」「项目信息」「设置」等；「项目信息」下可有「概览」「编辑」子项，或从项目详情进入后侧栏与 M1 项目详情一致，仅主内容区为 M2 页面。
- **主内容区**：背景 #F9FAFB，左右留白 24px，上留白 24px；内容最大宽度 1200px（表单页可 800px 内居中）。
- **规范引用**：字体、主色、按钮、卡片、表单均按《页面原型风格规范》执行。

## 3. P1 - 项目信息概览

### 3.1 布局

- 主内容区顶部：面包屑「项目管理 / [项目名] / 项目信息」；标题「项目信息」H1（20px，字重 600）；右侧「编辑项目信息」主按钮。
- 下方：左侧为「信息摘要」卡片区，右侧为「知识库就绪状态」卡片。

### 3.2 信息摘要卡片

- 卡片标题「信息摘要」H2（16px，字重 600）。
- 列表展示各字段是否已填写及摘要（首行或前若干字）：
  - 项目概述：已填写 / 未填写；若已填写显示前 1～2 行预览。
  - 架构说明：已填写 / 未填写；若已填写显示前 1～2 行预览。
  - 目录结构说明：已填写 / 未填写；若已填写显示前 1～2 行预览。
  - 关键模块说明：已填写 / 未填写。
  - 配置说明：已填写 / 未填写。
  - Runbook：已填写 / 未填写。
- 每项右侧可带「编辑」链接，跳转 P2 并定位到对应区块（可选）。
- 最后更新时间：12px 灰色，显示 updatedAt。

### 3.3 知识库就绪状态卡片

- 卡片标题「知识库就绪状态」H2。
- **就绪**：显示「已就绪」标签（绿色），说明「该项目可提交需求与 Bug」；可选显示 lastCheckedAt。
- **未就绪**：显示「未就绪」标签（警告色），说明「请完善以下内容后再提交需求」；下方列出缺失项（如：项目概述、架构或目录说明）。
- 操作：「编辑项目信息」主按钮（与顶部一致），未就绪时按钮可强调。

### 3.4 交互

- 点击「编辑项目信息」→ 跳转 P2。
- 从 M1 项目详情「去维护」进入本页时，侧栏保持当前项目上下文，高亮「项目信息」或「知识库」。

## 4. P2 - 编辑项目信息

### 4.1 布局

- 主内容区顶部：面包屑「项目管理 / [项目名] / 项目信息 / 编辑」；标题「编辑项目信息」H1。
- 下方单列表单卡片，最大宽度 800px，卡片内边距 24px。

### 4.2 表单项（自上而下）

| 标签 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 项目概述 | 多行文本 | 是（就绪规则） | 占位符「请描述项目用途、主要功能与边界」；建议 3～6 行 |
| 架构说明 | 多行文本 | 二选一必填 | 占位符「如架构图说明、技术栈、模块划分」；建议 4～8 行 |
| 目录结构说明 | 多行文本 | 二选一必填 | 占位符「如关键目录、文件组织说明」；与架构说明至少填一项 |
| 关键模块说明 | 多行文本 | 否 | 占位符「关键模块职责与入口」 |
| 配置说明 | 多行文本 | 否 | 占位符「环境变量、配置文件说明」 |
| Runbook | 多行文本 | 否 | 占位符「常见运维操作、故障处理步骤」 |

- 表单项间距 16px；标签与输入框间距 8px。
- 必填与「二选一必填」在标签旁用红色星号或说明文字标注；就绪规则说明可放在卡片顶部 12px 灰色提示：「至少填写项目概述，以及架构说明或目录结构说明之一，方可提交需求。」

### 4.3 底部操作

- 「取消」次要按钮 → 返回 P1，不保存。
- 「保存」主按钮 → 提交表单；成功后跳转 P1，Toast「保存成功，知识库就绪状态已更新」；若未就绪则提示还差哪些项。

### 4.4 校验与提示

- 前端可根据就绪规则做非空校验（项目概述必填；架构说明与目录结构至少一项非空）；后端最终校验并更新 KnowledgeReadiness。
- 提交失败时在表单上方或字段旁展示错误信息（错误色）。

---

## 5. 未就绪拦截页（需求提交入口内）

- 当用户在「提交需求」或「创建工单」入口选择某项目时，若该项目的知识库未就绪，调用 `RequireKnowledgeReady` 返回 4xx 后：
  - 展示提示条或弹窗：「请先完成项目信息与知识库维护，再提交需求。」
  - 提供「去维护」主按钮，跳转至 `/projects/:id/knowledge`（P1）。
- 可不单独做 M2 静态原型页，在需求提交页的交互说明中体现即可。

## 6. 原型文件与规范对应

- 色彩、字体、间距、按钮、表单、卡片、顶栏侧栏均按《页面原型风格规范》执行。
- 静态 HTML 原型位于 `docs/prototypes/m2/`，可直接在浏览器中打开查看布局与样式，交互以说明为准；实际项目以前端框架实现为准。
