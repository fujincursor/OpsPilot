Docker 核心概念图解

把「在我电脑上能跑」收成一只标准箱子：应用、运行时和系统库一起装进去，换一台机器打开，跑出来的还是同一只箱子。本页按学习顺序重画课程里的概念，图在前，命令在后。

看懂镜像、容器、Dockerfile 各管什么，以及它们怎么串起来。
会做构建镜像、映射端口、挂载数据、看日志、进容器排查。
用在 Agent统一开发环境、隔离执行代码的沙箱、把服务交付到任意机器。

阅读约 40 分钟。运维背景可以先看总图，再跳到 Dockerfile、卷和 Agent 沙箱。前端、DBA、应届生建议按目录往下走。正式课里的 Agent 平台会同时跑 FastAPI、PostgreSQL、Redis 和 Agent 运行时，Docker 是它们的统一打包标准。

02　容器不是缩小版虚拟机

两者都能隔开环境。差别在于：虚拟机连内核一起复制，容器只隔开进程，继续用宿主机的内核。

Docker 容器虚拟机
启动秒级分钟级
磁盘通常几十到几百 MB往往数 GB
内存共享内核，额外开销很小每个虚拟机自带操作系统
隔离进程级，内核仍是宿主机的硬件级，内核各自独立
适合把应用打包并部署需要跑另一套操作系统

类比：虚拟机是在房子里再盖一栋带独立水电的房子。容器是用隔板分房间，水电还是这一栋的。

03　三个词，三种角色

Image

镜像 · 图纸

只读模板。里面有代码、运行时、系统库、环境变量和启动命令。图纸不能住，但能盖出无数栋一样的房子。

python:3.12-slim
名字是 python，标签是 3.12-slim。同一名字可以有很多标签，指向不同版本。

Container

容器 · 房子

镜像跑起来的实例。同一张图纸可以同时盖三栋，住户互不看见对方的进程和文件系统改动。

停掉并删除容器时，没挂到外面的改动会一起消失。

Dockerfile

配方 · 施工说明

一个文本文件，一行一条指令。Docker 按顺序执行，每一条会变成镜像里的一层。

改配方再 docker build，得到新镜像，旧容器不会自动换成新的。

docker images
docker run -it --rm python:3.12-slim python3

-i 保持标准输入，-t 分配一个终端，--rm 让容器退出后自动删掉。三个旗标合在一起，适合「进去看一眼就走」。

05　日常就这几组命令

不必背手册。先把命令放回流水线的位置。

镜像

docker pull python:3.12-slim 下载

docker images 看看本地有什么

docker build -t agent-api:1.0 . 按 Dockerfile 构建，. 是上下文目录

docker history python:3.12-slim 看每一层的命令和体积

docker rmi python:3.12-slim 删除。还被容器占用时会拒绝

容器

docker run 创建并启动

docker ps 正在跑的；docker ps -a 连停掉的一起看

docker stop / start / restart 停、再开、重启同一个容器

docker exec -it my-app bash 进到正在跑的容器里敲命令

docker logs -f --tail=50 my-app 盯日志

docker rm 删已停止的；docker rm -f 连跑着的一起删

06　把 docker run 拆开看

这是用得最多的一条。每个旗标都在回答一个问题：后台吗、叫什么、门开在哪、数据放哪、配置从哪来、挂了怎么办、能吃多少内存。

docker run \
  -d 后台跑。不加的话，这个终端被占住，Ctrl+C 会把容器停掉
  --name agent-api 起名。否则会得到类似 jolly_curie 的随机名
  -p 8000:8000 宿主机端口 : 容器端口
  -v /host/data:/app/data 宿主机目录 : 容器目录
  -e DATABASE_URL=postgres://... 注入环境变量
  --restart unless-stopped 宿主机重启后自动拉起来，除非你手动停过
  --memory=512m 内存上限，避免一只容器吃光机器
  agent-api:1.0.0
不写会怎样结果
没有 -d前台占用终端
没有 --name随机名字，下次不好找
没有 -p容器里服务活着，外面进不去
没有 -v容器一删，里面写下的数据没了
没有 -e程序用默认值，或者直接因缺配置失败
没有 --restart机器重启后容器不会自己回来

07　端口：门外的号牌，不是屋里的插座

容器有自己的网络。默认情况下，宿主机的浏览器看不到容器里的 8000。 -p 是在门口挂一块号牌，把进来的人领到屋里指定的插座。

浏览器打开 localhost:8080 → 宿主机接收 → 转发进容器的 8000 → 进程必须在 0.0.0.0:8000 上听
听 0.0.0.0

门外的转发能进来

从容器看，宿主机转进来的连接来自「外面」。进程要听所有网卡。

uvicorn main:app --host 0.0.0.0 --port 8000

听 127.0.0.1

只有容器自己能访问

uvicorn 默认常常只听回环地址。这时 -p 已经配对，curl 仍然失败。门开了，插座只接在内墙。

docker run -p 8000:8000 my-fastapi-app
docker run -p 8080:8000 my-fastapi-app
docker run -p 127.0.0.1:8000:8000 my-fastapi-app
docker run -p 8000:8000 -p 5432:5432 my-app

第三行把号牌只挂在本机，局域网里的别人访问不到。EXPOSE 8000 只是说明书上的一句声明，真正开门的是 -p。

08　Dockerfile：一行一层

下面这份配方服务的是 FastAPI。先看每一行落在「构建」还是「启动」。

指令做什么何时发生
FROM选定基础镜像，文件的第一句构建
WORKDIR之后的命令都在这个目录构建
COPY把上下文里的文件放进镜像构建
RUN装依赖、编译。做完就冻成一层构建
ENV / ARG环境变量写进镜像；ARG 只在构建时传入构建
EXPOSE告诉读的人这个进程打算听哪个端口文档
CMD默认启动命令，容易被 docker run 后面的命令换掉启动
ENTRYPOINT固定要执行的程序，后面的参数更像追加启动

CMD 和 ENTRYPOINT：谁可以被观众改词

只有 CMD

剧本是 uvicorn main:app --port 8000。

你执行 docker run my-image python3，整场戏换成 python3。uvicorn 不会出场。

适合「默认这样跑，但允许人临时换一个命令」。

ENTRYPOINT + CMD

固定节目是 uvicorn main:app，默认台词是 --port 8000。

docker run my-image --port 9000 只换台词。实际执行变成 uvicorn main:app --port 9000。

九成场景用 CMD 就够。只有「容器必须跑这个程序」时才上 ENTRYPOINT。

docker build -t agent-api:1.0.0 .
docker run -d -p 8000:8000 --name agent-api agent-api:1.0.0
curl http://localhost:8000/health

09　让构建变快，让镜像变小

层缓存：不常变的放前面

某一层的指令或输入变了，这一层和它后面的层全部重做。依赖文件很少改，业务代码天天改，所以先复制依赖、先安装，最后才复制代码。

每次改一行代码都重装依赖

COPY . .
RUN pip install -r requirements.txt

代码一变，安装层的缓存失效。

代码变了，依赖层直接复用

COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .

一个容器一件事

API、数据库、Redis 分成三只容器，再用 Compose 编排。塞进同一只容器，日志、重启和扩容会缠在一起。

生产别用 latest

python:3.12.4-slim 今天和明天是同一个东西。latest 是会漂移的标签，构建结果会悄悄变。

.dockerignore

作用像 .gitignore。把 .git、.env、venv/、__pycache__ 挡在构建上下文外面，镜像更小，密钥也不会被 COPY 进去。

10　容器可以死，数据要留在外面

可写层的寿命默认等于容器。数据库文件、上传文件、要保留的日志，必须放在容器外面。

绑定挂载命名卷
位置你指定的宿主机路径Docker 管理的存储
谁负责你Docker
换机器路径经常对不上不依赖具体路径
开发首选，方便热重载也可以
生产数据少用首选

开发时的热重载

把当前目录挂进 /app，uvicorn 加上 --reload。你在编辑器里保存，容器里的进程看见文件变化后重启。macOS 和 Windows 的绑定挂载要多过一层虚拟化，文件监听有时发钝，可以改成轮询，或改用命名卷。

docker run -d -p 8000:8000 -v ${PWD}:/app my-fastapi-app

数据库删了容器，表还在

1volume create pgdata
→
2run 并挂到数据目录
→
3建表、插入
→
4rm 容器
→
5用同一卷再 run

验证标准不是「容器还在」，而是「新容器挂上同一个卷之后，昨天的行还在」。

11　同一个镜像，三套环境

密码和地址不要写进镜像。镜像保持一份，开发、测试、生产靠环境变量换配置。

docker run -e DATABASE_URL=postgres://localhost/mydb -e LOG_LEVEL=DEBUG my-app
docker run --env-file .env my-app

Python 里可以用 os.environ.get("DATABASE_URL", "sqlite:///./default.db") 给默认值。变量一多，用 Pydantic Settings 把缺了必填项这件事变成启动即失败，而不是跑到一半才发现是 None。

`.env` 里通常有口令。把它写进 .gitignore 和 .dockerignore。镜像层一旦包含密钥，删文件也清不掉那一层历史。

12　这门课后面，Docker 出现在三个地方

场景 1

统一开发环境

镜像里固定 Python 3.12、系统包、Python 依赖、pytest 和调试器。新人拉起来就能跑 uvicorn，不再对齐每人的本机。

场景 2

Agent 沙箱

模型写出的代码不要直接在宿主机执行。放进短命容器：跑完删除、不给网络、限制内存和 CPU、限制时间。

场景 3

打包交付

构建出版本号明确的镜像，推到仓库，任何服务器 pull 之后用同一条 run 启动。

docker run --rm --network none --memory 256m --cpus 1 python:3.12-slim python3 -c "print(1+1)"

交付时用明确版本：docker build -t agent-platform:1.0.0 .，打上仓库前缀再 push。另一台机器 pull 同一个标签，再 docker run -d -p 8000:8000。

13　让 API、数据库、Redis 互相叫名字

默认情况下容器彼此隔离。自定义网络里，Docker 内置 DNS：容器名就是主机名。API 连接 db:5432，而不是去猜一个会变的 IP。

docker network create agent-network
docker run -d --name api --network agent-network -p 8000:8000 agent-api
docker run -d --name db --network agent-network -e POSTGRES_PASSWORD=secret postgres:16
docker run -d --name redis --network agent-network redis:7-alpine

下一节 Docker Compose 会自动创建这张网。你写下服务名，服务之间用服务名互相访问。这一节先用手建网络，是为了看见 Compose 替你做了什么。

14　五个坑，按出现频率排

1. 服务只听 127.0.0.1

端口映射已经写了，外面还是拒绝连接。启动参数加上 --host 0.0.0.0。

2. 忘了 -p

docker ps 里容器是 Up，curl localhost:8000 失败。先看 PORTS 那一列是不是空的。

3. 数据写在容器里面

删容器等于删库。数据库目录、上传目录挂到卷上。

4. COPY . . 太老实

没有 .dockerignore 时，.env、.git、虚拟环境会进镜像。

5. 镜像肥、标签飘

用 slim 或 alpine 基础镜像，多阶段构建，清掉 apt 缓存。生产标签写死版本号。

清理命令要看清

docker system prune -a 会删掉没被容器使用的镜像、停止的容器和未使用的网络。默认不删卷。 要连卷一起清，才加 --volumes。那一步会删掉数据库文件。

16　动手练习

先自己做。参考命令折在下面，用来对答案，不用来代替动手。

基础 1 · 第一只容器

用 python:3.12-slim 打印 Hello, Docker!，退出后不要留下容器。

参考 
docker run --rm python:3.12-slim python3 -c "print('Hello, Docker!')"

基础 2 · 把 FastAPI 装进箱子

写 Dockerfile，build，再用 -p 8000:8000 运行。用 curl 打 /health。若连接失败，先查监听地址是不是 0.0.0.0，再查 docker ps 的端口列。

基础 3 · 进去看，再出来看日志

启动一只 python 容器并让它保持运行。 docker exec -it 进去执行 pip list。退出 shell 时容器还应是 Up。回到宿主机用 docker logs 看输出。

参考 
docker run -d --name pybox python:3.12-slim sleep 3600
docker exec -it pybox pip list
docker logs pybox

进阶 · 卷比容器活得久

创建 pgdata，启动 Postgres 并挂到数据目录，进容器建一张表。删掉容器，用同一卷再启动，确认行还在。

参考骨架 
docker volume create pgdata
docker run -d --name my-postgres -e POSTGRES_PASSWORD=secret -v pgdata:/var/lib/postgresql/data -p 5432:5432 postgres:16
docker exec -it my-postgres psql -U postgres
docker rm -f my-postgres
docker run -d --name my-postgres -e POSTGRES_PASSWORD=secret -v pgdata:/var/lib/postgresql/data -p 5432:5432 postgres:16

进阶 · 两份 Dockerfile 比体积

版本 A 用 python:3.12 单阶段。版本 B 用 builder 安装依赖，runner 用 python:3.12-slim 只复制运行所需文件。 docker images 对比 SIZE。

综合 · 开箱即用的 Agent 开发镜像

镜像里要有 Python 3.12、fastapi、uvicorn、httpx、pydantic、sqlalchemy、pytest、ipython，工作目录 /workspace，启动后进入 Python REPL。构建、运行、进容器确认包在。
