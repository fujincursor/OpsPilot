# M4 - 需求理解与分类 · 页面原型说明

本文档描述 M4 模块各页面的**原型结构、布局、组件与交互**，遵循 [页面原型风格规范.md](页面原型风格规范.md)。可配合 `docs/prototypes/m4/` 下的 HTML 静态原型查看效果。

---

## 1. 页面清单与路由

| 序号 | 页面名称 | 路由（示例） | 说明 |
|------|----------|--------------|------|
| P1 | 工单列表 | `/projects/:projectId/tickets` | 分页列表、筛选、提交需求入口 |
| P2 | 提交需求 | `/projects/:projectId/tickets/new` | 创建工单表单（标题、描述、附件） |
| P3 | 工单详情 | `/projects/:projectId/tickets/:ticketId` | 需求内容、分析结果、状态、下游入口 |

---

## 2. 全局布局（所有页面共用）

- **顶栏**：高度 56px，背景 #FFFFFF，下边框 1px #E5E7EB；左侧 Logo +「运维 Agent 工作台」；右侧「项目管理」「工作台」导航 + 用户头像下拉（退出等）。
- **侧栏**：宽度 220px，背景 #FFFFFF，右边框 1px #E5E7EB；当前项目下展示「概览」「需求」「设置」等子导航；「需求」对应 M4 工单列表与提交入口。
- **主内容区**：背景 #F9FAFB，左侧留白 24px，右侧留白 24px，上留白 24px；内容最大宽度 1200px（列表与表单页）。
- **规范引用**：字体、主色、按钮、卡片、表格均按《页面原型风格规范》执行。

---

## 3. P1 - 工单列表

### 3.1 布局

- 主内容区顶部：标题「需求与工单」H1（20px，字重 600）；副标题或面包屑：项目管理 / 项目名 / 需求。
- 下方：筛选栏 +「提交需求」主按钮（右对齐）；再下方为表格区域（卡片容器，白底，圆角 8px，内边距 24px）。

### 3.2 筛选栏

- **关键词**：单行输入框，占位符「搜索标题或描述」，宽度 200px。
- **类型**：下拉，选项「全部」「Bug」「新需求」，默认「全部」。
- **状态**：下拉，选项「全部」「待分析」「分析中」「已分析」「分析失败」，默认「全部」。
- **查询**：次要按钮「查询」；「重置」链接样式。
- 与表格间距 16px。

### 3.3 表格

| 列名 | 宽度 | 说明 |
|------|------|------|
| 标题 | 自适应 | 可点击进入工单详情；下方小字 12px 灰色显示创建时间、提交人 |
| 类型 | 90px | 标签：Bug（警告色）/ 新需求（信息色）；未分析时显示「-」 |
| 状态 | 100px | 待分析 / 分析中 / 已分析 / 分析失败（对应语义色标签） |
| 更新时间 | 120px | 日期时间，12px 灰色 |
| 操作 | 140px | 「查看」链接；分析失败时显示「重新分析」 |

- 表头背景 #F9FAFB，表头文字 14px 字重 600；行高约 52px；无数据时显示空状态插画 +「暂无工单，点击提交需求」。
- 底部分页：总数、每页条数选择（10/20/50）、上一页/下一页。

### 3.4 交互

- 点击「提交需求」→ 跳转 P2。
- 点击标题或「查看」→ 跳转 P3。
- 点击「重新分析」→ 二次确认后调用分析接口，列表或详情状态刷新。

## 4. P2 - 提交需求

### 4.1 布局

- 主内容区：面包屑「项目管理 / 项目名 / 需求 / 提交需求」；标题「提交需求」H1；下方单列表单卡片，最大宽度 560px，卡片内边距 24px。

### 4.2 表单项（自上而下）

| 标签 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 需求标题 | 单行输入 | 是 | 占位符「简要描述需求或问题」 |
| 需求描述 | 多行文本 | 建议必填 | 3～6 行，占位符「请详细描述现象、复现步骤或期望效果，便于 Agent 分析」 |
| 附件 | 上传 | 否 | 可选上传截图、日志等，展示已选文件列表与删除 |

- 表单项间距 16px；标签与输入框间距 8px。
- 说明文案（12px 灰色）：提交后将由 Agent 自动分析并区分为 Bug 或新需求，并进入对应流程。

### 4.3 底部操作

- 「取消」次要按钮 → 返回 P1。
- 「提交」主按钮 → 校验必填项；提交后创建工单并触发分析，跳转 P3 或 P1 并提示「需求已提交，正在分析中」。

### 4.4 校验与提示

- 标题、描述必填（或描述建议必填）；提交前若项目知识库未就绪，接口返回 4xx 时前端展示「请先完成该项目的知识库维护」并引导至 M2 入口。
- 提交失败时在表单上方或字段旁展示错误信息（错误色）。

## 5. P3 - 工单详情

### 5.1 布局

- 顶部：面包屑「项目管理 / 项目名 / 需求 / 工单标题」；标题区：工单标题 H1 + 状态标签（待分析/分析中/已分析/分析失败）+ 类型标签（Bug/新需求，已分析后展示）；右侧「返回列表」次要按钮。
- 下方两列：左侧主信息区（约 2/3），右侧状态与操作区（约 1/3）。

### 5.2 左侧 - 需求内容卡片

- 卡片标题「需求内容」；内容：需求描述正文（支持换行与简单格式）；若有附件，展示附件列表与下载链接。
- 下方卡片「分析结果」（仅当 status = analyzed 或 analysis_failed 时展示）：
  - **类型**：Bug / 新需求（标签形式）。
  - **范围摘要**：一段话描述（scopeSummary）。
  - **涉及模块/文件**：列表展示 affectedModules（若有）。
  - **置信度**：进度条或百分比（若有）；低置信度时可提示「建议人工确认」。
  - 若 status = analysis_failed：展示「分析失败」提示与「重新分析」主按钮。

### 5.3 右侧 - 状态与下游入口

- **状态**：卡片「工单状态」；当前状态、创建时间、更新时间、提交人。
- **下游入口**（仅当 status = analyzed 时展示）：
  - 若 type = bug：「进入修复方案」链接 → M5 方案页或 M7 待审列表。
  - 若 type = feature：「进入设计文档」链接 → M6 设计页或 M7 待审列表。
- 若 status = analyzing：展示「分析中，请稍候」及加载态；可轮询或 WebSocket 更新状态。

### 5.4 交互

- 「返回列表」→ 返回 P1。
- 「重新分析」→ 确认后调用分析接口，页面刷新或轮询直至分析完成/失败。
- 「进入修复方案」/「进入设计文档」→ 跳转至 M5/M6 或 M7 对应视图（路由由产品统一约定）。
