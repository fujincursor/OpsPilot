设计概述

在现有权限与操作体系基础上，新增「审计日志」领域模块。采用事件驱动方式：在关键操作（登录、登出、敏感配置变更、数据导出、角色/权限变更等）执行后，由各业务模块发布审计事件，由统一审计服务落库并支持按条件查询与导出。存储建议独立表或独立库，便于保留与合规；查询接口需支持按时间、操作人、操作类型、资源类型等筛选，并做分页与导出。前端在管理后台增加「审计日志」菜单，列表展示与导出能力与现有列表风格一致。

模块划分

  • 1. 审计领域模块（audit）

    负责审计事件的接收、持久化、查询与导出。职责：定义 AuditEvent 模型与存储表；提供 record(event) 与 query(filters, page) 接口；支持按条件导出 CSV/Excel。

  • 2. 审计事件发布（各业务模块）

    在登录/登出、配置修改、数据导出、权限变更等节点发布统一格式的审计事件至 audit 模块。职责：约定事件 schema（operatorId, action, resourceType, resourceId, detail, ip, timestamp）；在关键路径调用 audit.record()。

  • 3. 审计查询 API 与前端

    提供 REST 查询接口与管理后台「审计日志」页面。职责：GET /api/audit/logs 支持筛选与分页；前端列表、筛选、导出按钮，与现有后台风格一致。

接口说明

  • POST/api/audit/events
    内部调用，接收审计事件并落库

    Body: operatorId, action, resourceType, resourceId, detail?, ip?, timestamp。

  • GET/api/audit/logs
    查询审计日志，支持 operatorId, action, resourceType, startTime, endTime, page, pageSize

    返回分页列表与总数，供管理后台展示与导出。

  • GET/api/audit/logs/export
    按当前筛选条件导出 CSV/Excel

    需鉴权且仅限管理员或审计角色。
