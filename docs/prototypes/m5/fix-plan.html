根因分析

并发场景下，多个请求同时访问同一用户的 session 时，Redis 会话存储的读写未做串行化或锁保护，导致竞态条件。部分请求在 session 尚未完全写入或过期边界被清理时读取，触发空指针或序列化异常，进而返回 500。建议在 session 读写路径增加分布式锁或改用原子操作，并确保 session 过期与续期逻辑在并发下一致。

变更说明

  • 1. 登录成功后 session 写入
    src/auth/session_service.js
    约 45–78 行

    对「获取-修改-写回」改为单次原子写入，或对 key 加分布式锁后再读写，避免并发下覆盖或读到中间状态。

  • 2. Session 续期与过期检查
    src/auth/session_middleware.js
    约 22–35 行

    在续期时先加锁再读-续期-写回，确保同一 session 在并发请求下只被续期一次，避免重复删除或误删。

  • 3. Redis 连接与错误处理
    src/infra/redis_client.js
    可选

    对 Redis 超时与连接失败增加重试与明确错误码，避免将底层异常直接透传为 500，便于区分与告警。

建议涉及文件

src/auth/session_service.js src/auth/session_middleware.js src/infra/redis_client.js
