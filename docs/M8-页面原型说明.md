# M8 - 代码生成与语法校验 · 页面原型说明

本文档描述 M8 模块各页面的**原型结构、布局、组件与交互**，遵循 [页面原型风格规范.md](页面原型风格规范.md)。可配合 `docs/prototypes/m8/` 下的 HTML 静态原型查看效果。

---

## 1. 页面清单与路由

| 序号 | 页面名称 | 路由（示例） | 说明 |
|------|----------|--------------|------|
| P1 | 代码与校验列表 | `/projects/:projectId/code-changes` 或 `/code-changes?projectId=xxx` | 按项目筛选的代码变更列表，状态、Lint 结果、操作入口 |
| P2 | 代码变更详情（生成中） | `/tickets/:ticketId/code` 或 `/code-changes/:id` | 展示生成中状态、进度或文案，可轮询更新 |
| P3 | 代码变更详情（Lint 通过） | 同上 | 展示生成的代码/patch、Linter 通过、操作：进入测试 / 代码 Review |
| P4 | 代码变更详情（Lint 不通过） | 同上 | 展示生成的代码、Linter 错误列表（行号、消息）、操作：重新生成、再次校验 |

---

## 2. 全局布局（所有页面共用）

- **顶栏**：高度 56px，背景 #FFFFFF，下边框 1px #E5E7EB；左侧 Logo +「运维 Agent 工作台」；右侧「项目管理」「工作台」导航 + 用户头像下拉。
- **侧栏**：宽度 220px，背景 #FFFFFF，右边框 1px #E5E7EB；当前项目下展示「概览」「需求」「代码与校验」「设置」等子导航；可带「代码与校验」高亮。
- **主内容区**：背景 #F9FAFB，左右留白 24px，上留白 24px；内容最大宽度 1200px（列表与详情均适用）。
- **规范引用**：字体、主色、按钮、卡片、表格均按《页面原型风格规范》执行。

## 3. P1 - 代码与校验列表

### 3.1 布局

- 主内容区顶部：标题「代码与校验」H1（20px，字重 600）。
- 下方：筛选栏 + 表格区域（卡片容器，白底，圆角 8px，内边距 24px）。

### 3.2 筛选栏

- **项目**：下拉选择当前用户有权限的项目（若从项目上下文进入则可隐藏或默认当前项目）。
- **工单 ID / 标题**：单行输入，占位符「搜索工单」。
- **状态**：下拉，选项「全部」「生成中」「待校验」「已通过」「未通过」，默认「全部」。
- **查询**：次要按钮「查询」；「重置」链接样式。
- 与表格间距 16px。

### 3.3 表格

| 列名 | 宽度 | 说明 |
|------|------|------|
| 工单 | 自适应 | 工单标题（可点击进工单或代码详情）；下方小字 12px 灰色显示工单 ID、类型 Bug/新需求 |
| 状态 | 100px | 标签：生成中 / 待校验 / 已通过（绿）/ 未通过（红） |
| Linter | 100px | 通过 / 未通过 / —（未执行） |
| 版本 | 80px | 当前代码变更的 version |
| 更新时间 | 140px | 日期时间，12px 灰色 |
| 操作 | 140px | 「查看详情」「重新生成」（仅未通过时）、「再次校验」 |

- 表头背景 #F9FAFB，表头文字 14px 字重 600；行高约 52px。
- 无数据时显示空状态：插画或图标 +「暂无代码变更记录」+ 说明「方案 Review 通过后将自动触发生成」。
- 底部分页：总数、每页条数（10/20/50）、上一页/下一页。

### 3.4 交互

- 点击工单标题或「查看详情」→ 跳转 P2/P3/P4（按当前状态进入对应态）。
- 点击「重新生成」→ 二次确认，确认后调用生成接口，列表项状态更新为「生成中」或跳转详情页。
- 点击「再次校验」→ 调用 Lint 接口，列表项状态更新或跳转详情页查看结果。

## 4. P2 - 代码变更详情（生成中）

### 4.1 布局

- 面包屑：工作台 / 代码与校验 / 工单标题 或 工单 xxx / 代码与校验。
- 标题区：工单标题 H1 + 状态标签「生成中」橙色（warning）。
- 主内容：单栏卡片「代码生成中」；内容为进度文案（如「正在根据方案生成代码，请稍候…」）+ 可选 Loading 动画或骨架屏；支持轮询或 WebSocket 更新，完成后自动跳转「已生成」或「Lint 不通过」视图。

### 4.2 交互

- 可提供「刷新」按钮手动拉取最新状态；完成后自动跳转详情（P3 或 P4）。

---

## 5. P3 - 代码变更详情（Lint 通过）

### 5.1 布局

- 标题区：工单标题 H1 + 状态标签「已通过」绿色（success）；右侧操作「进入测试」（主按钮，跳转 M9 或工单测试 Tab）、「查看方案」（链接，跳转 M7 或方案展示）。
- 下方两栏或 Tab：
  - **代码变更**：卡片标题「生成结果」；展示 patch 差异或文件列表（文件名、路径、行数）；可展开查看具体代码块（只读），样式参考代码高亮。
  - **Linter 结果**：卡片标题「语法/静态检查」；显示「已通过」、使用的工具（如 eslint）、执行时间；无错误列表。

### 5.2 交互

- 「进入测试」→ 跳转 M9 测试执行或工单的测试 Tab。
- 「查看方案」→ 跳转 M7 或工单内方案 Tab。

---

## 6. P4 - 代码变更详情（Lint 不通过）

### 6.1 布局

- 标题区：工单标题 H1 + 状态标签「未通过」红色（error）；右侧操作「重新生成」（主按钮）、「再次校验」（次要按钮）。
- 上方可选提示条：警告色「存在语法/静态检查错误，请重新生成或修改后再次校验。」。
- 下方两栏或上下分区：
  - **代码变更**：同 P3，展示生成结果（patch 或文件列表），可只读展开。
  - **Linter 错误**：卡片标题「检查结果」；表格或列表展示：文件、行号、消息、严重级别（error/warning）；表头可带「文件」「行号」「描述」「级别」。底部显示使用的工具与执行时间。

### 6.2 交互

- 「重新生成」→ 二次确认（如「将根据最新方案重新生成代码，当前版本将保留为历史」），确认后调用生成接口，页面转为「生成中」或轮询直至完成。
- 「再次校验」→ 对当前代码变更再次执行 Linter，结果刷新到本页；若通过则状态变为「已通过」，可展示成功提示并引导「进入测试」。

---

## 7. 与工单详情的整合方式（可选）

- 若「代码与校验」作为工单详情页的一个 Tab：则 P2～P4 的内容嵌入工单详情页的「代码与校验」Tab 内，路由可为 `/tickets/:ticketId`，Tab 切换至「代码与校验」时展示上述布局与操作。
- 若为独立页面：则列表 P1 与详情 P2～P4 使用独立路由，从工单详情可跳转至「代码与校验」详情页。
