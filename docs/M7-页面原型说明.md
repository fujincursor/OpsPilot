# M7 - 人工 Review 工作台 · 页面原型说明

本文档描述 M7 模块各页面的**原型结构、布局、组件与交互**，遵循 [页面原型风格规范.md](页面原型风格规范.md)。可配合 `docs/prototypes/m7/` 下的 HTML 静态原型查看效果。

---

## 1. 页面清单与路由

| 序号 | 页面名称 | 路由（示例） | 说明 |
|------|----------|--------------|------|
| P1 | 待审列表 | `/reviews` 或 `/reviews/pending` | 分页列表、筛选、进入详情 |
| P2 | Review 详情（方案） | `/reviews/tasks/:id?type=plan` | 展示方案内容，通过/驳回 |
| P3 | Review 详情（代码） | `/reviews/tasks/:id?type=code` | 展示代码变更与 Lint 结果，通过/驳回 |
| P4 | Review 详情（测试报告） | `/reviews/tasks/:id?type=testReport` | 展示测试报告摘要，通过/驳回（可选） |

说明：P2～P4 可为同一详情页，根据待审任务 type 动态展示不同内容区域；或拆分为不同路由，原型中分别提供方案/代码/测试报告三种示例。

---

## 2. 全局布局（所有页面共用）

- **顶栏**：高度 56px，背景 #FFFFFF，下边框 1px #E5E7EB；左侧 Logo +「运维 Agent 工作台」；右侧「项目管理」「工作台」「Review」导航 + 用户头像下拉。
- **侧栏**：宽度 220px，背景 #FFFFFF，右边框 1px #E5E7EB；可展示「待审列表」或当前工单下的「方案 / 代码 / 测试报告」等子导航；与 M1/M4 风格一致。
- **主内容区**：背景 #F9FAFB，左右留白 24px，上留白 24px；内容最大宽度 1200px。
- **规范引用**：字体、主色、按钮、卡片、表格均按《页面原型风格规范》执行。

---

## 3. P1 - 待审列表

### 3.1 布局

- 主内容区顶部：标题「Review 工作台」或「待审列表」H1（20px，字重 600）。
- 下方：筛选栏；再下方为表格区域（卡片容器，白底，圆角 8px，内边距 24px）。

### 3.2 筛选栏

- **项目**：下拉，选项为当前用户有权限的项目列表，含「全部」。
- **待审类型**：下拉，选项「全部」「方案」「代码」「测试报告」，默认「全部」。
- **查询**：次要按钮「查询」；「重置」链接样式。
- 与表格间距 16px。

### 3.3 表格

| 列名 | 宽度 | 说明 |
|------|------|------|
| 工单标题 | 自适应 | 可点击进入 Review 详情；下方小字 12px 灰色显示工单类型（Bug/新需求）与提交人 |
| 项目 | 120px | 项目名称 |
| 待审类型 | 100px | 标签：方案 / 代码 / 测试报告 |
| 就绪时间 | 140px | 待审项创建时间，12px 灰色 |
| 操作 | 100px | 「去 Review」主色链接 |

- 表头背景 #F9FAFB，表头文字 14px 字重 600；行高约 52px。
- 无数据时显示空状态插画 +「暂无待审项」。
- 底部分页：总数、每页条数（10/20/50）、上一页/下一页。

### 3.4 交互

- 点击工单标题或「去 Review」→ 跳转 P2/P3/P4（根据该条 type 进入对应详情页或统一详情页并切换展示）。

---

## 4. P2 - Review 详情（方案）

### 4.1 布局

- 面包屑：Review 工作台 / 待审列表 / 工单标题 / 方案 Review。
- 标题区：工单标题 H1 + 待审类型标签「方案」；可选展示工单类型（Bug/新需求）。
- 主内容：左侧或全宽为「待审内容」卡片区（展示 FixPlan 或 DesignDoc 内容）；右侧或底部为「操作区」与「Review 历史」。

### 4.2 待审内容区（方案）

- **根因分析 / 设计概述**：卡片标题 + 正文（来自 FixPlan.rootCauseSummary 或 DesignDoc.overview）。
- **变更说明 / 模块与接口**：卡片标题 + 列表（变更项、涉及文件、说明）。
- **建议涉及文件**：标签形式展示 suggestedFiles[]。
- 样式与 M5 fix-plan、M6 设计稿展示一致，只读。

### 4.3 操作区

- **通过**：主按钮「通过」→ 提交 action=approve，可选填写简短意见；确认后调用接口，成功后提示「已通过」并跳转待审列表或工单详情。
- **驳回**：次要或危险按钮「驳回」→ 展开或弹窗：多行输入框「驳回意见」（必填），「确认驳回」「取消」；确认后调用 SubmitReview(reject, comment)，成功后提示「已驳回」并跳转。

### 4.4 Review 历史

- 卡片「Review 历史」：列表展示该工单下所有 ReviewRecord（时间倒序）；每条：操作人、通过/驳回、意见、时间；12px 灰色辅助信息。

### 4.5 交互

- 通过/驳回提交后，按钮置为 Loading 防重复；成功后可跳转待审列表或留在本页并刷新状态（若设计为同一工单多轮 Review）。

---

## 5. P3 - Review 详情（代码）

### 5.1 布局

- 与 P2 共用同一详情页框架；面包屑与标题区体现「代码 Review」。
- 主内容：**代码变更**展示区（diff 或文件列表 + 片段）；**Lint 结果**卡片（若有）；**操作区**与 **Review 历史** 同 P2。

### 5.2 代码变更展示

- 来自 M8 的 CodeChange：可展示 patch 文本（只读）、或「变更文件列表 + 每文件 diff」；风格与常见代码 Review 界面一致（如左右对比或行内 diff）。
- 若 Linter 已执行：单独卡片「语法/静态检查结果」，通过（绿）/ 失败（红），失败时列出错误行号与消息。

### 5.3 操作区与历史

- 同 P2：通过 / 驳回（驳回必填意见）；Review 历史列表。

---

## 6. P4 - Review 详情（测试报告）

### 6.1 布局

- 与 P2/P3 共用详情页框架；标题区体现「测试报告 Review」。
- 主内容：**测试报告摘要**（来自 M9 TestReport：总用例数、通过数、失败数、报告链接）；**操作区**与 **Review 历史** 同 P2。

### 6.2 操作与交互

- 通过：确认测试结果无误后通过，触发下游（如发布可选）。
- 驳回：可选；若支持则需填写意见，回退到重新测试或修复。
